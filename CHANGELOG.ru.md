## 4.0.0 — 2026-09-29

### Изменено
- **Адаптация к линии DSH 0.2.0**: `engines.dsh` и четыре peer-зависимости `@deepseek-ai/dsh-client-*` переходят на `>=0.2.0-rc.1 <0.2.1-0` (взамен диапазонов 0.1.7); npm dist-tag `dsh-0.2.0`; версия манифеста выровнена по `4.0.0`. Поверхность API, используемая плагином (manifest / settings / HMR / slots / сессия v4), по сравнению с 0.1.7 не изменилась — правок исполняемого кода нет.
- Нижняя граница peer-зависимости `@deepseek-ai/cordis` выровнена по `^4.0.4` (пакеты UI хоста 0.2.0-rc.1 объявляют `~4.0.4`; прежний `^4.0.1` её принимал, но занижал нижнюю границу).

### Исправлено
- `src/client/family-section.tsx` взят под контроль версий (с 3.2.x он существовал только в рабочем дереве, из-за чего чистый checkout не мог собрать проект).
- eslint flat config: удалено ядрёное правило `no-unused-vars` — оно ложно помечало параметры в сигнатурах типов TS; вариант typescript-eslint сохранён, lint-базовая линия снова зелёная.
- Статические шлюзы source-kind v4 (`tests/source-kind.test.mjs`) взяты под учёт и выполняются в `npm test` (248 тестов).

## 3.2.4 — 2026-09-27

### Исправлено
- **Адаптация к формату сессии v4 (хост >= 0.1.7-rc.1)**: три пути записи сессии больше не используют выведенную из обращения подпись `source: { kind: 'plugin', plugin: 'session-guard' }`, которую хост v4 отклоняет с `SessionFormatError` (падает весь раунд). Все три теперь используют kind во владении производителя:
  - инъекция уведомлений отложенного возобновления (`src/wiring.js`);
  - инъекция уведомлений автоповтора (`src/retry.js`);
  - followup пауза-возобновление (`src/pause-gate.js`, ```kind: `plugin:${pluginId}````).
  - **Нативная адаптация tool-result под v4 (N1)**: `findToolOutcome` в `src/pause-gate.js` теперь сначала читает нативное сообщение v4 первого класса `role:'tool'` (`toolCallId`/`isError` на верхнем уровне сообщения); путь v3 через блоки `tool-result` сохранён как исторический резерв. Без этого сбойный на момент паузы инструмент при возобновлении докладывался как выполненный («не перезапускать») — тихое ошибочное решение. `src/tool-call-id.js` сначала читает нативный id верхнего уровня; устаревшие примечания в заголовках эпохи 0.1.1/0.1.2 исправлены на таблицу трёх форм по поколениям.
  `form` и все остальные поля не изменились; собственная миграция хоста v3→v4 поднимает существующие исторические строки, поэтому исторические данные не перезаписываются. Доказательство: `@deepseek-ai/dsh-session-format-v3-to-v4@0.1.7-rc.2` проверяет лишь, что `source.kind` непустой и не равен `'plugin'`.

## 0.4.0 — 2026-09-18 (ошибочная версия; заменена на 3.0.0)

## 3.0.0 — 2026-09-14

### Изменено

- **Выделенная линия для DSH v0.1.5-rc.2 (`compat/0.1.5`).** Диапазоны `engines.dsh` и peer-зависимостей
  `dsh-client-*` сужены до `>=0.1.5-rc.2 <0.2.0-0` (строгое semver-сопоставление prerelease означает, что старый
  диапазон `>=0.1.0-rc.7` никогда не совпадал с `0.1.5-rc.2`); `dsh.plugin.json` получил `engines.dsh`.
  Линия 2.x / 0.2.x на `main` продолжает обслуживать DSH 0.1.0-rc.7 … 0.1.2-rc.1.
- **`session.events` → `snapshotEvents()`.** DSH 0.1.5 удалил доступ к массиву `session.events`
  (compatibility-guide §20.3). `pause-gate.js` теперь читает события сессии через
  вспомогательный двойной путь: сначала `snapshotEvents()`, старый массив `events` как защитный
  резерв, `null` (fail-open), если нет ни того ни другого. Затрагивает только `findToolOutcome` и
  `lastUserPrompt`; сопоставление типов событий не меняется.

### Без изменений

- Ноль изменений на всех прочих стыках интеграции: собственный префиксный маршрут webServer
  (`/session-guard/rpc`), `settings.register`, слот `settings.plugin.item`, клиентские инъекции и
  `llm.listConfigurableProviders()` — все проверены на целостность относительно опубликованного бандла 0.1.5-rc.2
  (`tools/check-api-drift.ps1`, 12/12 обязательных утверждений).

### Ожидается

- Живой smoke-тест на реальном хосте DSH 0.1.5-rc.2 (тот же статус, что у линии 0.1.5 perm-gate).

## 0.2.0-beta.2 — 2026-09-13

### Исправлено (совместимость с DSH 0.1.5 — ветка `compat/0.1.5`)

- **Двойной путь постановки в очередь при возобновлении.** DSH 0.1.5 превращает Inbox в проекцию
  agent-loop только для чтения, поэтому `agent.followup` может больше не существовать. Поток возобновления
  теперь сначала пробует `agent.followup`, затем откатывается к `agent.send`, а при недоступности обоих
  деградирует до предупреждения (никогда не бросает исключение) — неудачная постановка в очередь больше не ломает возобновление.
- **Сообщения возобновления несут `source.form: 'instructions'`** согласно контракту источников сообщений
  `ContextFormed` из 0.1.5 (`kind: 'plugin'` — встроенный kind; старые версии DSH игнорируют
  дополнительное поле).
- **`webServer.register` обёрнут в try/catch**: неудачная регистрация маршрута теперь записывает
  ошибку в журнал вместо вылета из `apply` и поломки загрузки плагинов хоста.
- Проверено по исходникам 0.1.5-rc.2: контракт `WebRoute` (exact/prefix + SSE) не изменился, поэтому
  клиентским `fetch('/session-guard/...')` префикс `/api` не нужен.

## 0.2.0-beta.1 — 2026-09-10

### Добавлено

- **Ворота уровня шага (`agent/pre-step`).** В часы пик раунд теперь удерживается **до** запроса
  к модели следующего шага, а не обрывается на границе раунда: сессия продолжает работать до следующего
  `agent/pre-step`, где ворота её удерживают (настройка `stepLevelPause`, по умолчанию
  включена). Внепиковое время раунд возобновляется **на месте** — сообщение followup не требуется. Условия удержания:
  пик (пекинское время) + не выходные + `step > 1` + официальный целевой провайдер (`providerGuard`) +
  нет удержания на уровне запроса + не обойдено вручную в этом пиковом окне. Новый модуль `src/step-gate.js` (чистый
  `decideStepHold` + движок hold / release / abort / timeout).
- **Порт `stepResume` + RPC + `/resume`.** `sessionGuard.stepResume(sessionId, {bypass})`,
  `POST /session-guard/rpc {action:'stepResume'}` и `/resume` — все открывают ворота; ручное
  возобновление также прекращает управлять этой сессией до конца пикового окна.
- **Повышение по таймауту.** `stepGateTimeoutMs` (по умолчанию 300000) открывает ворота и повышает до
  **принудительной** паузы на уровне раунда, так что долгий пик не приводит ни к дедлоку, ни к «капельнице» по шагу каждые пять минут.
- **Кнопка «⏸ Пауза сессии»** (клиент, slot `conversation.input.right`, id `session-guard-pause`,
  order 20 — слева от кнопки заморозки input-traffic). Она опрашивает `/session-guard/state` раз в секунду,
  остаётся неактивной, пока ничего не удерживается, и вызывает `stepResume`, когда удерживается. Бейдж состояния переехал на
  order 40 и теперь показывает число сессий, удержанных на уровне шага.
- **Новые настройки**: `stepLevelPause`, `stepGateTimeoutMs`.
- **Новые состояния**: `GET /session-guard/state` теперь возвращает `paused: { step, turn }` и
  `stepGate: { held, since, bypass }`; `/status` возвращает `stepHeld`; `/diag` возвращает `stepGate`.
  `state().paused` порта сервиса остаётся булевым для совместимости (новое поле `pausedStep`).

### Исправлено

- **Дедлок между удержанным шагом и паузой уровня раунда.** `pauseTask` / `resumeTask` /
  `cancelTask` теперь сначала открывают ворота шага: удержание шага сидит на `agent/pre-step`, куда никогда
  не могут прийти `assistant/message` или `tool/result`, поэтому `safe`-пауза ждала вечно и
  не сохраняла `paused`.

### Изменено

- **Вход в пик больше не прерывает идущие раунды** при включённом `stepLevelPause` (`onEnterPeak` взводит
  ворота шага вместо вызова `stopNextTurn`); при выключенном прежнее поведение уровня раунда сохраняется.
- Подпись кнопки заморозки input-traffic теперь **"Freeze & append"** (`冻结追加` / `凍結して追加` /
  `동결 후 추가`), подпись возобновления — **"Resume & append"** (`恢复追加` / `再開して追加` /
  `재개 후 추가`) — она замораживает раунд и сохраняет поставленные в очередь сообщения, отдельно от кнопки паузы.
- **Кнопка паузы стала переключателем**: «Пауза сессии» / «Продолжить сессию» (серое неактивное состояние убрано).
  Нажатие «Пауза сессии» вызывает новое действие `stepPause`, которое удерживает сессию на **следующей
  границе шага** (шаг 1 тоже, независимо от пика или провайдера); «Продолжить сессию» вызывает
  `stepResume`. Новый метод порта `sessionGuard.stepPause(sessionId)`.
- **SSE-пуш**: новый маршрут `GET /session-guard/events?session=<id>` доставляет изменения состояния
  ворот шага в момент их возникновения, поэтому автоматические удержания пика переключают кнопку на
  «Продолжить сессию» без ожидания опроса; опрос `/session-guard/state` раз в 10 с остаётся резервом. `/state` теперь сообщает
  `paused.manual` и `stepGate.manual`.
- **Стиль выровнен** с кнопкой composer у input-traffic (высота 24 px, радиус 6 px, шрифт 12 px, те же
  токены border/hover/pressed) — и для кнопки паузы, и для бейджа состояния; стили инъецируются
  один раз через `<style data-plugin-css="session-guard-client">`.

## Не выпущено

### Добавлено

- **Двухмерная стража официальных источников (пик × целевой провайдер).** В часы пик блокируются только
  запросы, чей целевой маршрут — официальный источник DeepSeek; локальные/сторонние провайдеры продолжают
  работать. Порядок вердикта: явный список id `officialProviders` → живой эндпоинт `baseURL` →
  встроенный в каталог эндпоинт (`deepseek` у pi-ai) → встроенный id (`deepseek-official`); каждый вердикт
  сообщает `matchedBy`. Новые модули: `src/provider.js` (чистый), `src/provider-directory.js`,
  `src/deferrals.js`, `src/request-guard.js`, `src/targets.js`, `src/wiring.js`.
- **Страховка уровня запроса (`agent/request`).** Покрывает сессии, запущенные после входа в пик, и
  сессии, переключённые на официальный источник на ходу — тик 30 с обрабатывал только сессии, уже бывшие
  `running` к моменту перехода. Режим `hold` по умолчанию приостанавливает запрос без ошибки
  и выпускает его в точный момент выхода из пика (`msUntilOffPeak`); режим `error` бросает узнаваемый
  отказ `PEAK_DEFERRED` и регистрирует отложение для возобновления в непик.
- **Новые настройки**: `providerGuard`, `officialProviders`, `officialBaseURLs`, `deferredResume`,
  `deferredResumeText`, `deferredMode`, `deferredMaxHoldMs` (по умолчанию 6 ч), `guardSubagents`.
- **Новые маршруты**: `GET /session-guard/provider?provider=<id>` (диагностика вердикта);
  `/session-guard/status` теперь сообщает `providerGuard` / `held` / `deferred`;
  `/session-guard/state` сообщает последнюю цель сессии.
- **Страж дрейфа** `tools/check-api-drift.ps1`, утверждающий наличие требуемых API на
  `dsh-v0.1.1-rc.2` / `dsh-v0.1.2-rc.1` / `dsh-v0.1.3-alpha.2` / `dsh-v0.1.5-alpha.1`.

### Изменено

- **Поддержка двух версий DSH (0.1.0-rc.7 … 0.1.2-rc.1).** Один артефакт теперь покрывает и
  `dsh-v0.1.1-rc.2`, и `dsh-v0.1.2-rc.1`. Двойное чтение id вызова `tool/result`
  (сначала `content[].toolCallId`, резерв `source.callId` — обе формы встречаются в журналах воспроизведения
  обеих версий) вынесено в не имеющий зависимостей `src/tool-call-id.js` с модульными тестами.
  `dsh.client.inject` больше не называет `@deepseek-ai/dsh-client-runtime` (удалён в 0.1.2) и
  `@deepseek-ai/dsh-client-ui-slots` (не динамическая клиентская строка); диапазоны peer-зависимостей расширены до
  `>=0.1.0-rc.7 <0.2.0-0`, удалённый пакет исключён. Добавлены `engines.dsh` и
  таблица совместимости версий в README (ZH/EN).
- **Поверхность настроек остаётся на API пересечения**: только `settings.register` + `settings.get`;
  `installSection` (0.1.2+) и удалённый `installSettingsSection` никогда не используются. Необязательные
  API (`model/selection`, `llm.listConfigurableProviders`, `settings.get`) проверяются зондированием функций и
  деградируют вместо исключений.
- **`src/retry.js` коротит только точный маркер `PEAK_DEFERRED`.** Отказы 429 / `RATE_LIMIT` /
  `TRANSPORT` / таймаут остаются переходящими, поэтому глобальный повтор DSH (`dsh-llm-retry` на
  `agent/request-error`) и собственная семантика повтора плагина не меняются. `dsh-llm-retry`
  сам по себе не трогается никогда.
- Бейдж различает «пик · только официальные» и «пик · все на паузе».

## 0.1.1 — 2026-08-24

### Добавлено

- **Автоповтор на стороне бэкенда (D9)**: переходящие сбои `turn/end` (error/429/max-tokens) запускают возобновление `followup(retryText)` с адаптивной задержкой; постоянные сбои (аутентификация/баланс/модель/лимит контекста) останавливают; вмешательство пользователя или успешный раунд сбрасывают счётчик последовательных сбоев.
- **Уступание при заморозке/воротах**: повтор пропускается, когда `isFrozen(sessionId)` истинно (queueLocked / paused / taskControl paused), сессионные ворота никогда не обходятся.

### Изменено

- Избыточный порт `sessionGuard` теперь предоставляет `state(sessionId)`, возвращающий `{ queueLocked, lockReason, paused, taskControlAvailable, taskControl }`.
- HTTP-маршрут `GET /session-guard/diag` возвращает диагностику времени выполнения, включая состояние повтора.

### Исправлено

- Определение выходных теперь использует `Intl.DateTimeFormat` с настроенным часовым поясом вместо голого `getUTCDay()`, что устраняет 8-часовую граничную ошибку для пекинского часового пояса.
